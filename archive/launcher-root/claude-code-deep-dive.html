Multi-Agent

Multi-Agent Coordination

coordinator/ · Feature-flagged · Production-ready orchestration

Pattern: A coordinator Claude instance orchestrates multiple worker Claude instances via the AgentTool. Workers receive a filtered tool subset and share a scratchpad directory.
TypeScript // Task type prefixes type TaskType = | 'b' // local_bash | 'a' // local_agent | 'r' // remote_agent | 't' // in_process_teammate | 'w' // local_workflow | 'm' // monitor_mcp | 'd' // dream // Task ID: 8-char base-36 random // 36⁸ ≈ 2.8 trillion unique IDs const taskId = prefix + nanoid(8, BASE36)
🧠
Coordinator System Prompt — injected directives for task delegation, worker monitoring, and result aggregation.
🔧
Filtered Worker Tools — workers only receive: Bash, FileRead/Write/Edit, Glob, Grep + MCP tools. No recursive agent spawning.
📂
Scratchpad — shared directory (tengu_scratch feature) for durable cross-worker knowledge transfer.
📨
Task Notifications — worker results returned as <task-notification> XML blocks in the coordinator's context.
🎨
Color Management — each worker agent gets a unique terminal color for output disambiguation.

State Management

Zustand-style immutable store · state/ directory

🔒
Immutable Updates — all state changes via spread operators. No direct mutations. Enables undo + time-travel debugging.
📡
Observer Pattern (store.ts) — multiple listeners subscribe to state changes: UI, side-effect bus, persistence layer.
⚡
Memoized Selectors — derived state is computed only when dependencies change, preventing unnecessary React re-renders.
🔄
Side Effect Bus (onChangeAppState.ts) — settings sync, memory extraction, and session persistence triggered reactively.
💾
Session Persistence — conversation history serialized to ~/.claude/projects/ for cross-session resume.

Plugins (~/.claude/plugins/)

  • Versioned — multiple versions side-by-side
  • Remote-managed — auto-update from backend
  • Install/remove — via /plugins command
  • Bundled at startup — compiled into tool pool
Skill format — skills are markdown files with YAML frontmatter defining name, description, and trigger conditions. Claude reads the skill content and follows it as instructions.
Markdown --- name: my-skill description: What this skill does triggers: - when user asks about X - before doing Y --- # Skill instructions here Step 1: Do this... Step 2: Then do that...
ToolSearch — a dedicated tool that fuzzy-searches available skills and returns their schemas, enabling Claude to discover and invoke skills it wasn't pre-loaded with.
