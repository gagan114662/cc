Design Decision · Replay Method

One question determined the entire evaluation architecture

❓
Question asked:
"How should benchmark case replay actually execute? The 3 corpus cases have prompts and rubrics, and evaluationCommand is currently unset. Running experiments 1-7 requires scoring candidates against those cases at least 5 times each."
Option A
Claude API (LLM-as-judge)
Call claude-sonnet-4-6 via API, feed each case prompt + rubric, score pass/fail. Fully automated, unattended.
Option B — SELECTED ✓
Claude Code subprocess
Shell out to claude CLI in a temp workspace with the mutation applied. Closest to real usage; slower but higher fidelity.
Option C
Manual annotation
Real Claude Code sessions, annotated by hand, submitted via CLI. No automated runner needed.
✅
Impact of this choice: The replay script must create a sandbox copy of the repo, apply the candidate's mutation, run claude as a subprocess per case per pass, and collect + score the output. This requires a working claude binary in PATH.

Plan · Replay Script Logic

scripts/autoresearchReplay.ts — step by step

  • Read AUTORESEARCH_CANDIDATE_MANIFEST → parse CandidateManifest. Extract workspacePath (the mutation overlay directory).
  • Load corpus from AUTORESEARCH_REPO_ROOT/autoresearch.seed-corpus.json. Get AUTORESEARCH_REPLAY_COUNT (default 5).
  • For each corpus case × N passes:
    a. cp -r $REPO_ROOT $TMP_SANDBOX (exclude .git, node_modules)
    b. Overlay candidate's changedFiles from workspacePath
    c. Run claude --dangerously-skip-permissions --output-format json -p <prompt> (90s timeout)
    d. Score output via single Claude API call checking rubric items + objective signals
  • Aggregate N passes per case → one CaseRunResult. stabilityScore = pass_count / N. Counts are medians.
  • Run challenge set: inject synthetic prompts for each of the 4 challenge candidates; check if expected failure tags appear.
  • Write CandidateEvaluation JSON to AUTORESEARCH_EVALUATION_OUTPUT.
Env vars consumed
AUTORESEARCH_REPO_ROOT # repo dir AUTORESEARCH_CANDIDATE_MANIFEST # input JSON path AUTORESEARCH_EVALUATION_OUTPUT # output JSON path AUTORESEARCH_REPLAY_COUNT # default 5
Output shape (CandidateEvaluation)
{ caseResults: CaseRunResult[], challengeResults: ChallengeResult[], benchmarkStabilityRate: 0..1, dogfoodMissRate: 0..1 }
⚠️
Requires claude binary in PATH. Each pass runs a full Claude Code session — 5 passes × 3 cases = 15 claude invocations per experiment.

Plan · Run Order

One experiment per session — trust floors between each

Per-experiment workflow

Submit candidate
bun run autoresearch:run-experiment --experiment exp-1 --replays 5
Drops manifest into incoming/candidates/
Controller cycle runs (5 min cadence)
15 claude invocations per experiment (5 passes × 3 cases). ~15-30 min wall time.
Check scorecard
bun run autoresearch:status --json
Verify eligibleForPromotion + all trust floors.
Pass → advance to shadow lane
Promotion decision: promote_shadow. Run 2 more real sessions as shadow evidence before dogfood.
Fail → reject, do not proceed
Any trust metric regression = hard reject. Fix the hypothesis before moving to exp-2.

Ladder gate rules

🚫
Stop if any trust metric regresses. Don't run the next experiment until the current one is resolved. A challenge escape triggers teacher freeze immediately.
✅
Promote only if: trust perfect + at least one of task_success_rate, artifact_validity_rate, token_cost_delta_pct improves vs. the baseline champion.
🔭
Honeycomb check per experiment: autoresearch_experiment_scored event with candidate_revision = "exp-N-v1". All trust fields must show at reliability floor.

shadow (2) → dogfood (2) → canary (3) → mainline
