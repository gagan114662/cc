Part 1 — Where the Agent Went Wrong

01 High Glob scoped to project root — twice tool misuse repeated

The agent's first action was two parallel Glob calls, both with path: "/Users/gaganarora/Desktop/my projects/cc" — the project root. Both triggered the pre-tool-use hook warning:

"⚠️ GLOB SCOPE WARNING: path='…/cc' — this root contains node_modules and will return thousands of irrelevant files. Scope to 'src 2/' or a specific subdirectory."

The warning fired for both calls simultaneously. Despite being caught by the hook, the agent still received noisy output (node_modules READMEs) for the *.md search and had to wade through it. The same mistake was then repeated later in the same session when checking for session-review*.html.

Root cause: The instruction in both CLAUDE.md files to scope Glob to src 2/ was read after the first tool call, not before. The agent evaluated the file-exists check (was analysis-deck.html already written?) without first checking where it should look.

What happened
Glob("analysis-deck.html",
  path: "/Users/gaganarora/Desktop/my projects/cc")
// → hook warning + noisy results
Should have been
Glob("analysis-deck.html",
  path: "/Users/gaganarora/Desktop/my projects/cc/src 2")
// → direct hit, no noise

Time lost: The result was truncated mid-output (thousands of node_modules files), forcing the agent to continue regardless. The correct file location (src 2/) was only discovered later by the research agent, not the main agent.

3
Upgrade the Glob scope hook from warning to blocking
Fixes: Incident 01 — hook warned but agent proceeded anyway

The current pre-tool-use hook emits a warning when Glob is scoped to the project root. The agent received the warning and still used the (noisy, truncated) results. A warning that doesn't change behaviour is not effective.

Upgrade the hook to block the tool call (non-zero exit) with a corrective message:

# In settings.json hooks:
{
  "event": "PreToolUse",
  "matcher": "Glob",
  "command": "node -e \"
    const input = JSON.parse(process.argv[1]);
    const p = input.tool_input?.path ?? '';
    const bad = [
      '/Users/gaganarora/Desktop/my projects/cc',
      '/Users/gaganarora/Desktop/my projects'
    ];
    if (bad.some(b => p === b || p === b + '/')) {
      process.stderr.write('BLOCKED: Glob at repo root. Use path: \\'src 2/\\' instead.');
      process.exit(1);
    }
  \" \"$CLAUDE_TOOL_INPUT\""
}

A blocked call forces the agent to correct the path before retrying, rather than silently consuming noisy output.

The CLAUDE.md auto-harness section is comprehensive but framed around feature development (before/after measurements, evidence manifests). It doesn't directly address static HTML output tasks. Add a lightweight "HTML output checklist" section:
