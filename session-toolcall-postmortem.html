Executive Summary

Big picture

  • The agent did eventually find the correct workflow: read the repo docs, run bun run repo:facts, analyze targeted files, write an HTML artifact in the repo root, then validate it with report:check and report:open.
  • The main wrong turns were orientation mistakes, not implementation mistakes. The session lost time before the agent fully trusted the repo’s own onboarding path.
  • The best prevention changes are mostly repo ergonomics changes: enforce search excludes by default, validate onboarding docs against the live tree, expose a machine-readable preflight summary, and make the “do not treat this as a git checkout” fact impossible to miss.
  • Some helpful repo assets already exist: START_HERE.md, project-context.json, ARCHITECTURE.md, CLAUDE.md, repo:bootstrap, repo:facts, and the report validation scripts all materially helped the recovery.

Specific Repo Changes

Concrete additions or edits I would make

1. Materialize the exclude policy

Generate a root .rgignore from project-context.json.search_excludes. That aligns the machine-readable onboarding file with the shell defaults.

2. Add doc drift tests

Parse ARCHITECTURE.md, START_HERE.md, and README.md for referenced files and fail CI if paths do not exist.

3. Expose repo state early

Teach repo:bootstrap to print or emit is_git_repo, code_root, and default excludes.

4. Add an HTML template

A checked-in report-template.html would let future agents skip format setup and move directly to analysis.

5. Make “docs first” harder to miss

Keep START_HERE.md, but echo its key lines in repo:bootstrap, and consider a short repo:onramp.json for automated clients.

6. Add a real verify-all path

A broad verification script would give agents a default “prove it” command rather than ad hoc checking.

Bottom Line

The agent’s biggest time loss was not “bad analysis.” It was delayed trust in the repo’s own onboarding path.

Once the session followed the repository’s documented flow, progress became efficient and deterministic. The most valuable changes are therefore the ones that make the correct path the default: enforce search excludes automatically, validate docs against the tree, surface git/non-git state immediately, and provide a ready-made HTML report template plus a one-command verification target.
